## 문제

"어려운 답장 문제"는 성격이 다른 세 문제다.

| 읽는 쪽 | 자료 | 결과 |

### 문제 1. 평가가 실패를 찾지 못한다 (측정)

- 천장 효과: 실제 모델이 거의 만점이다. 98/100도 95% 신뢰구간은 약 93~99.5%라 프롬프트를 고쳐도 좋아졌는지 가를 수 없다.
- 독립성: 문장과 정답을 쓴 쪽이 모두 프롬프트나 판정 기준을 봤다(B, C, C 쪽 Claude).
- 현실성: 모두 지어낸 문장이다. 실제 업체 문자는 저장소에 넣을 수 없다(`AGENTS.md`).
- 표본: 유형마다 9~16건이고, 어려운 답장은 한 번만 돌렸다.

### 문제 2. 오류마다 위험이 다른데 똑같이 센다 (지표)

| 오류 | 결과 | 위험 |
|---|---|---|
| 아무 유형 → `unknown` | 사용자가 버튼으로 고른다 | 낮음 |
| 제시가 아닌데 금액을 읽음 / 금액을 잘못 읽음 | 수용선 경고와 반박 금액이 틀어진다 | 높음 |
| 수용이 아닌데 `accept` | 법정 환불액으로 합의 처리로 넘어간다(`engine.py:147`) | 가장 높음 |
| 거절 ↔ 정상가 같은 유형끼리 혼동 | 반박 문안이 엇나간다 | 중간 |

#73부터 사용자가 확정해야 기록되지만, 사람은 미리 채워진 값을 그대로 믿기 쉽다. "안전하게 틀리는가"를 따로 재야 한다.

### 문제 3. 키워드 판정이 땜질로 흔들린다 (제품)

- 같은 거절 판정을 #70 → #81 → #83 → #91로 네 번 고쳤고, 고칠 때마다 다른 문장이 깨졌다.
- 변형(띄어쓰기, 붙여 쓰기, 부정의 부정)에 같은 답을 내는지 보는 시험이 없어 리뷰에서 손으로 찾았다.
- 위험 오류 25건 중 24건이 "금액이 보이면 무조건 `low_offer`" 규칙에서 나온다.
- 키가 없거나 하루 상한을 넘었을 때 쓰인다. 심사 기간에 상한을 넘으면 실제로 쓰인다.

## C — 평가

### C1. 위험 등급별 오류표 (11/19, 문제 2)

- `eval/run.py`의 `score`가 오류를 등급으로 센다.
  - 위험: 수용이 아닌데 `accept`, 제시가 아닌데 금액을 읽음, 금액을 잘못 읽음
  - 중간: 유형끼리 혼동
  - 안전: `unknown`
- 보고할 지표: 위험 오류율, 안전하게 틀린 비율(오답 중 `unknown`의 비율), 유형별 혼동 행렬.
- 정확도에는 95% 신뢰구간(Wilson)을 함께 적는다.
- `backend/tests/test_eval_run.py`에 등급 분류 테스트를 넣는다.
- 첫 기준선: 키워드 판정의 오답 107건 중 위험 25건, 안전 80건(2026-11-18, A가 임시로 셈).

### C2. 변형 시험 생성기 (11/19~20, 문제 1·3)

- `eval/perturb.py`가 기존 64건(기본 30 + 처음 보는 34)에서 정답이 유지되는 변형을 만든다.
  - 불변 시험: 띄어쓰기 없애기, 흔한 오타, 줄임말(ㅇㅋ, ㄴㄴ), 존댓말과 반말 바꾸기, 앞에 인사말·사정 설명 붙이기, 뒤에 ㅋㅋ·이모티콘. 유형과 금액이 바뀌면 안 된다.
  - 방향 시험: 금액 표기 바꾸기(20만 원 / 200,000원 / 이십만 원), 금액 바꾸기. 제시액만 따라 바뀌어야 한다.

## A — 화면

### A1. 독립적으로 쓴 답장 15~20건 (11/19, 문제 1)

- 프롬프트와 판정 기준표를 보지 않고 쓴다.
- 상황: 회원이 "가상피트니스 회원권(90일, 60만 원)을 개인 사정으로 오늘 해지합니다. 이용분 66,666원과 위약금 60,000원을 뺀 473,334원을 환불해 주세요"라고 보냈다. 업체의 답장이나 통화 메모를 쓴다.
- 업체 입장을 골고루(들어줌, 깎음, 버팀, 미룸, 엉뚱한 소리, 연락 안 됨). 말 돌리기, 앞뒤 다른 말, 반말·줄임말·오타, 긴 설명 끝 결론, 금액 여러 개.
- 한 줄에 `답장 | 업체가 진짜 하려는 말`. 이 메모가 정답의 근거다.
- 공개 사례(소비자원 사례, 뉴스, 커뮤니티 후기)는 말투만 참고하고 원문·업체명·연락처는 넣지 않는다.
- 파일: `eval/hard_replies_a.jsonl`. `eval/`은 C 담당이라 PR 본문 맨 위에 담당 밖 파일 표를 넣는다.

### A2. 확인 화면의 위험한 읽기 방어 (11/20, 문제 2)

- 먼저 지금 화면을 본다. 읽은 결과가 `accept`·`low_offer`일 때 확정 버튼 앞에 금액과 원문의 해당 부분이 눈에 띄는지.
- 부족하면 보강한다.
  - 키워드로 판단한 경우("키워드로 판단했어요")에는 `accept`와 금액을 미리 채우지 않고 사용자가 고르게 한다.
  - 합의로 넘어가기 전에 금액을 다시 확인하게 한다.
- 바꾸면 `harness/ui_flow.py`에 확인 항목을 더한다.
