# 부록: C 트랙의 AI 활용 내역 (파트 2)

> 초안 메모(제출 전에 지우기): 파트 1(`제출_C트랙.md`)에서 따로 뺀 부록이다. 팀 전체의 「제품 안에서 쓰는 AI」(`gpt-6.1-terra`의 다섯 기능, 누적 API 비용, 하루 호출 상한)는 소개서 부록의 가절과 `제출_B트랙.md` 6~7절에 있어 여기서는 되풀이하지 않는다. 여기는 C 트랙이 **개발에서** AI를 어떻게 썼는지만 적는다. `[제출 전 확인]`이 붙은 곳은 저장소로 확인되지 않는다.

## 1. 쓴 도구

| 도구 | 쓴 곳 |
|---|---|
| Claude Code | 문서·양식·테스트 작성과 수정, PR 본문과 커밋 메시지 초안, 다른 트랙 PR의 리뷰 초안 |
| Codex | 변경을 올리기 전의 교차 검증(두 번째 의견) |
| 제품 안의 `gpt-6.1-terra` | C는 직접 호출하지 않았다. 실제 모델로 돌린 평가는 모두 B가 실행했다(`docs/평가_결과.md` 머리말) |

## 2. AI가 한 일과 사람이 한 일

| 쓴 곳 | AI가 한 일 | 사람(C)이 한 일 |
|---|---|---|
| 환불 규칙과 근거 | 정본 문장을 읽고 줄여 정리하는 초안, 조정 사례 원문의 날짜를 세어 대조하는 보조 `[제출 전 확인: AI가 도운 범위]` | 어떤 근거를 표에 넣을지, 확인됨으로 바꿀지 정하기. 국가법령정보센터 원문 확인 |
| 문안 양식 | 업체 사정 문구와 통화 대본 대답의 초안과 수정, 소비자 사정 문안이 그대로인지 64건 비교 | 문구의 범위와 인용할 조문 정하기, 단정 표현이 없는지 읽기 |
| 평가 자료 | 어려운 답장 100건의 문장과 정답 초안(프롬프트를 보지 않은 Claude), 7건의 업체 사정 답장 | 판정 기준표를 정하고 판단이 갈릴 만한 4건을 직접 확인하기 |
| 변형 시험 | 규칙 스크립트(`eval/perturb.py`)로 변형 435건 생성 | 변형 규칙과 판정 방향 정하기 |
| 코드 리뷰 | 다른 트랙 PR의 diff를 읽고 직접 돌려 본 뒤 승인 여부와 댓글 초안 작성 | 댓글을 직접 올리고 승인과 병합 결정 `[제출 전 확인: 리뷰한 PR 수]` |
| 교차 검증 | 변경 묶음마다 Codex에 줄 요청문 작성, 돌아온 지적을 확인해 반영 | Codex에 요청문을 넣고 결과를 가져오기. 반영할 지적 고르기 |
| 숫자와 줄 번호 정리 | 실행 결과와 diff로 문서의 테스트 수와 줄 번호를 다시 계산 | 어떤 숫자를 어떤 출처로 쓸지 정하기 |
| 문서 | `docs/평가_결과.md`, `docs/환불_규칙.md`, 이 제출 자료의 초안 | 방향을 정하고 숫자와 문장을 확인해 고치기 `[제출 전에 실제로 확인한 뒤 남기기]` |

## 3. 사람이 쥐고 있던 것

- **커밋·푸시·PR은 사람이 말할 때만 했다.** AI가 문서나 코드를 고쳐도 그 작업에 대해 사람이 직접 요청하기 전에는 커밋하지 않았다.
- **PR 댓글과 승인은 사람이 올렸다.** AI는 글만 만들었다.
- **유료 호출은 하지 않았다.** C 트랙은 실제 모델을 부르는 평가를 직접 돌리지 않았다.
- **병합 전 승인 확인.** 승인은 특정 커밋에 붙기 때문에, 승인 뒤에 커밋이 추가되면 알려서 최신 커밋의 승인을 확인했다.

## 4. AI를 쓰면서 지킨 것

- **금액은 AI가 만들지 않는다.** 문서나 문안의 금액은 `rules.py`의 계산 결과만 쓴다.
- **근거는 확인된 표 안에서만.** 법령이나 조문 번호를 AI가 지어내지 못하게, `data/rules.json`에 없는 근거는 문안에 넣지 않는다(`AGENTS.md`).
- **가상 데이터만 쓴다.** 실제 계약서, 실제 업체 문자, 개인정보는 저장소·평가 자료·AI 요청에 넣지 않았다 `[제출 전 확인]`.
- **프롬프트를 보지 않는다.** C는 답장 읽기·분석·조언의 LLM 지시문을 읽지 않았다. 독립적으로 평가 자료를 쓰려는 것이다. 다만 판정 기준표를 쓴 C가 기준을 알고 문장을 쓴 자료는 독립 수집이 아니라고 한계에 적었다.
- **테스트는 키 없이.** 서버 테스트는 가짜 LLM으로 통과해야 한다.
- **숫자는 출처와 함께.** 모든 평가 숫자에 실행한 커밋, 실행한 사람, 한계를 같이 적었다. 확인하지 못한 것은 확인하지 못했다고 적었다.
- **AI의 결과는 다시 확인한다.** 줄 번호처럼 AI가 옮기기 쉬운 값은 코드와 diff로 다시 계산했고, 소비자 사정 문안이 바뀌지 않았는지 비교했다.

## 5. AI와 일하며 생긴 문제와 대응

- 수정 스크립트의 문자열 이스케이프 오류로 코드가 깨진 적이 있다. 테스트 수집 오류로 바로 드러나 되돌려 고쳤다. 그 뒤로 한글 문장을 바꾸는 스크립트는 정확히 한 곳만 바뀌는지 확인하고 실행한다.
- 승인 뒤에 추가된 커밋이 후속 리뷰 없이 병합된 일이 여러 번 있었다. 병합 전에 승인된 커밋과 현재 커밋을 비교해 알리도록 했다. 이번 제출 직전에도 한 번 있었다(#173).
- 문서의 숫자(테스트 수, 하니스 수)가 코드 변경 뒤에 옛 값으로 남는 일이 반복돼, 마지막에 한 번에 다시 맞췄다. 하니스 숫자는 C가 직접 돌리지 못해 A와 B의 보고를 인용했다.

## 6. 쓰지 않은 것

- AI에게 업체나 사용자에게 보낼 글의 내용을 맡기지 않았다. 문안은 C가 정한 고정 양식이고, AI는 양식 초안과 검사를 도왔다.
- AI가 사건 단계나 금액을 바꾸게 하지 않았다.
- AI가 평가의 정답을 확정하게 하지 않았다. 어려운 답장 100건의 정답 초안은 AI가 썼지만 사람이 4건만 확인했고 나머지는 "아직 확인하지 않음"으로 적었다.
