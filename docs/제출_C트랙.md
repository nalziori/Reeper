# Reeper 제출 자료 초안 — C 트랙(환불 규칙·근거 표·문안 양식·평가)

> 초안 메모(제출 전에 지우기): `제출_B트랙.md`와 같은 틀로 쓴 C 트랙 몫이다. 「파트 1」이고, AI 활용 내역은 「파트 2」로 `제출_C트랙_부록_AI활용.md`에 따로 뺐다. 숫자와 문장은 2026-11-22 기준 `main` `0a45ca0`의 저장소 문서로 확인했다. `[제출 전 확인]`이 붙은 곳은 저장소로 확인되지 않아 사람이 보고 남기거나 고쳐야 한다.

숫자의 출처는 `docs/환불_규칙.md`, `docs/평가_결과.md`, `eval/README.md`다. 예외는 셋이다. 간이 설문은 팀이 만든 구글 폼의 응답이라 저장소에는 집계만 있다. 실제 모델로 돌린 평가는 모두 B가 실행했다(`docs/평가_결과.md` 머리말). 브라우저 하니스 숫자는 A가 실행하고 B가 확인한 보고다.

## 1. 맡은 범위

C 트랙은 Reeper에서 **금액과 글의 근거**를 맡았다. LLM이 닿지 않는 부분이다. 파일로는 `backend/app/rules.py`, `data/`, `eval/README.md`와 C가 쓴 평가 답장, `docs/환불_규칙.md`, `docs/평가_결과.md`, `backend/tests/test_rules.py`, `backend/tests/test_mediation_cases.py`다.

| 기능 | C가 한 일 | 결과가 쓰이는 곳 |
|---|---|---|
| 환불 계산 | `rules.py`가 환불액, 이용분, 위약금, 하루 늦을 때 줄어드는 금액(`per_day_loss`)을 계산한다. 업체 잘못이면 위약금 0원으로 계산하고, 업체가 다퉈 소비자 사정으로 볼 때의 금액(`disputed_refund`)을 같은 날짜로 함께 낸다 | 화면의 예상 환불액, 문안의 금액, 하한선 경고 기준 |
| 근거 표 | `data/rules.json`에 근거 항목 11개를 두고, 모두 국가법령정보센터 정본과 대조했다(`verified: true`). 요약 문장은 원문을 줄인 것이다 | 문안과 AI 분석이 가리키는 근거. 표에 없는 근거는 문안에 넣지 않는다 |
| 문안 양식 | `data/templates/`의 고정 양식. 화면에 나가는 기본 양식 16종과, 업체 사정 사건에만 쓰는 숨은 양식 2종(위약금 반박, 통화 대본의 상대 반응 대답) | 사용자가 그대로 보내거나 읽는 글 |
| 평가 설계 | 답장 읽기의 판정 기준표(`eval/README.md`), 평가 답장 작성, 위험 등급 지표, 변형 시험 | B 트랙의 모델 평가와 키워드 판정의 기준 |
| 근거 조사 | 조문 원문 대조, 조정 사례 대조, 계산식 결정 근거 정리(`docs/환불_규칙.md`) | 위 모두의 출처 기록 |
| 간이 설문 | 구글 폼 응답 17건을 읽고 집계 | 소개서의 문제 설명 |

## 2. 설계 원칙: 계산과 근거에서 하지 않은 것

- **금액은 `rules.py`만 만든다.** LLM과 문안 양식은 숫자를 계산하지 않고 서버가 준 값을 끼운다.
- **"확인됨"으로 적힌 근거만 쓴다.** 원문을 읽은 사람과 날짜를 `docs/환불_규칙.md`에 적은 뒤에 `rules.json`에 옮긴다. 조정 사례와 소비자분쟁해결기준은 합의 권고라 근거 표에 넣지 않았고, 문안에도 법적 기준처럼 쓰지 않는다.
- **단정하지 않는다.** "정상가 차감은 무효", "한 번도 안 갔으면 대부분 돌려받는다", 환불을 "받을 수 있다"는 확정은 쓰지 않는다. 금액은 "일반적인 기준에 따른 예상 금액"이고 법률 자문이 아니다.
- **결정한 것과 원문이 정한 것을 구분한다.** 해지 의사 도달 당일을 이용일에 넣는 것, 원 단위 끝전을 버리는 것, 월 단위도 날짜로 일할하는 것은 고시에 규정이 없어 팀이 정한 계산 방식이다. 표에 출처(조정 사례)를 적고 법적 기준처럼 쓰지 않는다.
- **업체 잘못은 사용자가 고른 대로 계산하되 조건을 붙인다.** 앱은 귀책을 판정하지 않는다. 위약금 0원은 "귀책 없을 때만 청구할 수 있다"(고시 제4조 제1항)의 반대해석이라고 문서에 밝혔다. 화면은 "업체 잘못으로 인정되면"이라는 조건과, 업체가 다투면 줄어들 수 있는 금액(`disputed_refund`)을 함께 보여 준다.
- **업체가 위약금을 빼고 달라 할 때도 문안은 한정된 근거만 쓴다.** 업체 사정 반박 양식은 고시 제4조 제1항만 인용하고, 금액은 서버가 계산한 환불액 하나만 쓴다. 이용료 10%를 더하는 배상은 근거를 원문으로 대조하지 못해 계산과 문안에서 뺐다(C 결정, 2026-11-19).
- **새 문안이 기존 문안을 바꾸지 않게 한다.** 업체 사정 문구를 더할 때마다 소비자 사정 문안이 바뀌지 않았는지 계약 4개 × 양식 16종(64건)으로 비교했다(#162, #165). 업체 사정 전용 칸은 해당 사건에서만 채워지고 소비자 사정에서는 빈 문자열이다.
- **모든 양식은 검사를 통과해야 한다.** 새 양식은 `validate`를 통과해야 하고, 업체 사정 사건에서도 모든 양식을 다시 검사한다.

## 4. 근거를 확인하며 정한 것

- **업종은 둘이다.** 위약금 기준(총계약대금의 10%)이 확인된 업종은 헬스·피트니스업과 요가·필라테스업이다. 그 밖의 업종이면 계산 금액 대신 1372 상담을 안내한다. 고시 본문에 PT라는 말이 없어, PT를 헬스·피트니스업에 넣은 것은 화면의 판단이라고 문서에 적었다.
- **이용분은 날짜로 일할한다.** 월 단위 계약도 같다(2026-11-20 변경). 확인한 헬스 회원권 조정 사례들이 날짜로 일할했기 때문이다. 단가는 실제 결제한 총액을 계약 일수로 나눈다(공정위 특수거래과 답변). 장기 할인 계약의 단가를 1개월 표준가로 보는 의결도 있어, 업체가 그 기준을 들면 앱 금액보다 이용분이 커질 수 있다고 한계로 적었다.
- **날짜 세기와 끝전.** 소비자24 조정 사례 5건의 원문을 받아 날짜를 직접 세어 대조했다(2026-11-21). 도달 당일을 이용일에 넣은 사례가 있었고, 한 건(11731)은 통지한 날의 전날까지 셌다. 고시에는 규정이 없어 팀이 정한 방식이다.
- **업체 잘못 조정례.** 업체 쪽 사정이 다퉈진 조정례 7개 중 6개에서 위약금을 공제하지 않았고, 소비자 사정으로 본 1건(13849)만 공제했다. 다만 사건마다 판단 이유가 달랐다. 그래서 "업체 잘못으로 인정되면"이라는 조건을 금액과 함께 보인다.

## 5. 알려진 한계

고칠 수 있는 것은 고쳤고, 아래는 이번 제출에서 고치지 않기로 한 것이다.

**계산과 근거의 한계**

- 계산은 헬스·피트니스와 요가·필라테스 회원권만 다룬다. 휴회 기간, 총액의 일부만 낸 계약, 업체 귀책 배상(이용료의 10%)은 계산하지 않는다.
- 개시 전 해지의 기준(소비자분쟁해결기준)은 원문과 적용 범위를 대조하지 못해 근거 표에 넣지 않았다(C 결정). 그래서 개시 전 해지 상황의 안내는 근거가 얇다.
- 도달 당일 포함과 끝전 버림은 고시에 규정이 없는 팀 결정이다. 앱은 첫 통지를 기록한 날을 도달일로 본다. 실제로 업체에 닿은 날은 확인하지 않는다.
- 위약금 0원 계산은 반대해석이다. 조정에서는 업체 잘못을 선택해도 소비자 사정으로 볼 수 있다.
- 입금 기한은 주말을 뺀 3영업일로 센다. 공휴일 목록이 없고 법정 기산점과 같은지는 확인하지 않았다.
- 조정 사례와 공정위 답변은 약관 시정과 민원 답변이라 법적 기준이 아니다. `rules.json`에 없어 문안의 근거로 쓰지 않는다.

**문안의 한계**

- 업체 사정 사건의 양식 중 `counter_list_price`, `counter_visit`, `counter_low_offer`에는 해지 이유 구절이 없다(C 양식, 이번 제출에서 고치지 않았다).
- 통화 대본의 상대 반응 대답은 사용자가 읽는 말이다. 받아들일지 판단은 사용자가 한다.
- 반박 뒤 제시액이 하한선 이상이고 희망 금액 미만이어도 엔진은 1372로 보내고 이유 문구가 같다(A 확인 사항).

**평가의 한계**

- 평가 답장은 판정 기준표를 쓴 C가 기준을 알고 쓴 것이다. 독립적으로 수집한 자료로 보기 어렵다. 어려운 답장 100건은 사람이 4건만 확인했고 96건은 아직이다. 변형 435건은 사람이 확인하지 않았다.
- 업체 사정 답장은 7건이고 유형마다 1~4건이다. 실제 업체 문자는 개인정보라 저장소에 넣을 수 없어 모두 지어낸 문장이다.
- 키워드 판정의 위험 0건은 평가 자료를 보며 규칙을 고친 뒤의 숫자다.
- 실제 모델 실행은 모두 B가 했고 대부분 한 번씩이다.
- 간이 설문은 17건이고 배포 경로와 중복 응답 여부를 기록하지 않았다. 사용자 테스트는 하지 않았다.
