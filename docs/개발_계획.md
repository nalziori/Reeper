# 개발 계획

작성일: 2026-11-14 / 제출 마감: 2026-11-23 17:00 / 3명이 만든다

날짜별 일정은 두지 않는다. 단계마다 통과 조건을 두고, 조건을 채우면 다음으로 간다. 제품 내용은 [기획안](기획안.md), 코드 사이의 약속은 [계약](계약.md)을 따른다.

## 목표와 범위 가드

> **근거를 다 찾아 두고, 그대로 보내거나 말할 문장을 만들어 주고, 환불금이 계좌에 들어올 때까지 추적한다.**

| 기둥 | 에이전트가 하는 일 | 사람이 하는 일 |
|---|---|---|
| 1. 근거 | 계약 내용 읽기, 법정 환불액 계산, 조문 근거 연결, 하루 미룰 때 줄어드는 금액 표시 | 불확실한 값 확인 |
| 2. 문장 | 그대로 보낼 문자 문안, 통화 전에 꼭 말해야 할 것 정리, 업체 반응에 맞는 다음 문장 | 직접 보내고 직접 말함 |
| 3. 추적 | 도달일과 기한 관리, 무응답 시 다음 단계, 합의 후 입금 기한, 입금 확인으로 종결 | 보냄·통화함·답장·입금을 기록 |

- **범위 가드**: 새 기능은 세 기둥 중 하나에 속할 때만 넣는다.
- **에이전트가 하지 않는 것**: 전화 걸기, 문자·메일 발송, 통화 듣기, 답장 자동 수신, 법적 판단 확정.
- **만들지 않는 것**: 음성 인식·합성, 통화 중 실시간 보조, AI 사장과의 리허설, 로그인·회원, 헬스장 외 업종, 폐업·소송 대응, 알림 발송 서버.

## 사용자 여정

1. **계약 넣기**: 샘플 계약서, 사진 올리기, 직접 입력 중 하나. 자신 없는 값은 표시하고 확인받는다.
2. **근거 보기**: 환불액, 계산 내역, 조문 근거, "하루 미루면 −N원". 목표 금액과 최저 수용선을 정한다.
3. **말할 준비**: 문자 문안 또는 통화 준비 카드(첫마디, 꼭 말해야 할 것 다섯 가지, 예상 반론별 한 줄 대응).
4. **기록**: "보냈어요"나 "통화했어요"를 누르면 도달일이 정해진다. 통화였다면 통화 직후 보낼 확인 문자를 준다.
5. **기다림**: 답변 기한과 남은 날을 보여 준다.
6. **대응**: 답장을 붙여넣거나 통화 내용을 적으면, 읽고 분류해 다음 문장을 준다.
7. **무응답**: 기한이 지나면 재요청, 그다음 내용증명 초안, 마지막은 1372 소비자상담센터 연결.
8. **입금까지**: 합의 금액과 입금 기한을 기록하고, 늦으면 입금 요청 문안, 입금 확인으로 종결.

## 개발 방식

- **걷는 뼈대 먼저**: 가장 얇은 한 줄기를 가짜 응답으로 끝까지 연결한 뒤 살을 붙인다.
- **계약 우선**: 사건 상태, 이벤트, API, LLM 함수의 입출력을 먼저 고정하고 각자 가짜 구현으로 병렬 개발한다.
- **정답이 있는 부분은 테스트 먼저**: 환불 계산, 기한, 단계 전이.
- **LLM 부분은 평가 먼저**: 정답 세트를 먼저 만든다. 일반 테스트는 가짜 LLM으로 돌리고, 실제 API는 평가 실행 때만 쓰며 비용을 기록한다.
- **항상 배포 가능한 main**: 짧은 브랜치, PR, 리뷰 1명, CI(서버 테스트와 화면 빌드).
- **수직 조각 단위**: 한 조각은 화면·서버·테스트가 함께 끝난다.

## 아키텍처 결정

| 결정 | 내용 | 이유 |
|---|---|---|
| 서버 | Python, FastAPI. 상태를 저장하지 않는다 | 계약 정보를 서버에 남기지 않아 개인정보 부담이 없고 어디든 배포된다 |
| 사건 저장 | 브라우저 localStorage | 로그인 없이 다시 들어와 이어 간다. 다른 기기 이어하기는 하지 않는다 |
| 규칙의 위치 | 단계 전이와 금액 비교는 서버의 순수 함수 | 화면은 보관만 하고 판단은 서버 규칙이 한다. 테스트가 쉽다 |
| 화면 | React 19, Vite, TypeScript, Tailwind CSS 4, shadcn/ui(Base UI) | 2026-11-19 Astryx에서 바꿈. 같은 화면을 둘로 만들어 비교한 뒤 글·상자 크기가 맞는 쪽을 골랐다 |
| 배포 | 컨테이너 하나. FastAPI가 `/api`와 빌드된 화면을 함께 서빙 | 심사위원은 링크 하나로 접속한다 |
| LLM | OpenAI API, 모델명은 환경변수 | 예산 10달러. 제공자를 바꿔도 `agent.py`만 고친다 |
| LLM의 역할 | 계약서 읽기, 답장 읽기, 말투 다듬기 | 규칙으로 못 받는 입력만 맡긴다 |
| 문안 | 고정 양식에 값 채우기가 기본. LLM이 다듬은 문장은 `validate`를 통과해야 쓴다 | 금액과 조문을 지어내지 못하게 한다 |

화면은 `frontend/src/ui/`의 부품만 가져다 쓴다. 이 부품은 `frontend/src/components/ui/`의 shadcn 부품(Base UI + Tailwind) 위에 있다. 색·글꼴·모서리는 `frontend/src/index.css`의 토큰에서 정한다. 대표색은 주황(#F37021)이고, 주황 위 글자는 짙은 갈색, 흰 바탕 위 주황 글자는 #A8460B다.

## 단계와 통과 조건

**0단계 — 정의 고정** (사람)
- 고시 별표 원문으로 계산 규칙을 확정한다: 일할 계산, 개시 전 해지, 횟수제, 할인가, 환급 기한. [환불 규칙](환불_규칙.md)의 확인 기록에 적는다.
- 운영사무국 문의(배포 링크 필수 여부, 가상 데이터로 외부 AI 사용), 참가 신청, 간이 설문 배포.
- 통과 조건: 기간제 회원권 계산식이 원문으로 확인된다.

**1단계 — 걷는 뼈대** (완료, 배포만 남음)
- 통과 조건: 접수 → 환불액 → 문안 → 기록 → 대응 → 합의 → 입금 확인이 가짜 LLM으로 끝까지 가고 테스트가 통과한다. 배포 링크에서도 같다.

**2단계 — 병렬 수직 조각** (3명)
- 통과 조건: 실제 LLM으로 모든 경로가 끝까지 간다. 수용, 저액 제시 후 반박, 정상가 주장, 방문 요구, 무응답 → 재요청 → 내용증명 → 1372, 합의 → 입금 지연 → 입금.

**3단계 — 평가와 강화**
- `eval/run.py`로 측정하고 실패 사례를 고친다. 일반 LLM과의 비교, 건당 비용, 사용자 테스트 3~5명.
- 실제로 되는 것과 시연용 모의를 화면에 구분한다. 오류 상태와 모바일 화면을 다듬는다.
- 통과 조건: 아래 완료 기준을 모두 채우고 `docs/평가_결과.md`가 있다.

**4단계 — 제출**
- 기능 동결, 소개서, AI 활용 내역, 시연 영상 백업.
- 통과 조건: 팀원이 아닌 사람이 링크만 받아 혼자 3분 안에 종결까지 간다.

## 3인 트랙 (2단계)

| 트랙 | 맡는 것 | 주요 위치 |
|---|---|---|
| A — 엔진과 화면 | 단계 전이 보강, 화면을 여정 단계별로 나누기, 계약 확인·목표 금액 입력, 타임라인, 사건 파일 내보내기, 시연 조작, 배포 | `engine.py`, `main.py`, `frontend/` |
| B — 에이전트 | OpenAI 구현과 일일 호출 상한, 계약서 읽기와 확신도, 답장 읽기, 말투 다듬기, 실패 시 가짜 구현으로 대체 | `agent.py` |
| C — 규칙과 콘텐츠 | 근거 표 확인, 계산 함수 확정과 테스트, 문안 양식 다듬기, 가상 계약서와 정답, 답장 평가셋, 평가 스크립트, 설문 | `rules.py`, `data/`, `eval/` |

- A는 B·C의 함수를 호출만 한다. B·C는 사건 상태를 직접 바꾸지 않는다.
- 답장 평가셋 30개는 세 명이 10개씩 쓴다.
- 리뷰: A의 PR은 B가, B의 PR은 C가, C의 PR은 A가 본다. [계약](계약.md) 변경은 세 명이 모두 본다.

## 우선순위

- **반드시**: 샘플·직접 입력, 기간제 환불 계산과 근거, 문자 문안, 통화 준비 카드와 통화 후 확인 문자, 보냄·통화 기록, 답장 읽기와 다음 문장, 무응답 경로, 합의와 입금 추적, 타임라인, 시연 조작, 평가 스크립트.
- **가능하면**: 계약서 사진 올리기, 말투 선택(정중·단호), 횟수제 PT, 기한 캘린더 파일, 일반 LLM 비교, 환불을 막는 특약 표시.
- **여유 있으면**: 1372 신청서 초안, 사건 파일 가져오기, 어두운 화면.
- **늦어질 때 줄이는 순서**: 여유 있으면 → 가능하면(뒤에서부터) → 내용증명을 안내 문구로 축소. "반드시"의 여정은 유지한다.

## 비용과 보안

- 개발과 CI는 가짜 LLM이 기본이다. 실제 호출은 배포 환경과 평가 실행에서만 한다.
- 배포 환경에는 일일 전체 호출 상한, 입력 길이·이미지 크기 제한을 둔다. 상한을 넘으면 고정 양식과 버튼 입력으로 계속 진행하고 화면에 표시한다.
- API 키는 서버 환경변수에만 둔다. 서버는 계약 내용을 저장하지 않고 로그에도 남기지 않는다.
- 실제 계약서 사진 올리기는 운영사무국 답을 받기 전까지 꺼 둔다.

## 완료 기준

- 로그인과 마이크 없이, 데스크톱과 모바일 모두에서 3분 안에 종결까지 간다.
- LLM이 실패해도 고정 양식과 버튼으로 끝까지 진행된다.
- 환불액이 가상 계약서 정답과 일치한다.
- 문안에 표 밖의 금액이나 조문이 0건이다.
- 최저 수용선보다 적은 제시액에는 항상 경고가 뜬다.
- 통화 준비 카드에 꼭 말해야 할 다섯 가지가 들어 있다.
- 화면과 소개서에 실제로 되는 것과 시연용 모의가 구분되어 있다.
- 일반 테스트는 키 없이 통과한다.
