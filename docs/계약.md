# 계약

트랙 사이의 약속이다. 원본은 `backend/app/models.py`이고, 화면 쪽 사본은 `frontend/src/api.ts`다. 바꿀 때는 둘과 이 문서를 같이 고치고 세 명이 모두 본다.

## 원칙

- 서버는 사건을 저장하지 않는다. 화면이 사건을 보관하고, 요청에 실어 보내면 서버가 규칙을 적용해 돌려준다.
- 단계 전이와 금액은 서버 규칙이 정한다. LLM은 사건을 직접 바꾸지 않는다.
- 날짜(`today`)는 화면이 보낸다. 시연에서는 며칠을 건너뛴 날짜를 보낸다.

## 사건 (Case)

| 필드 | 뜻 |
|---|---|
| `contract` | `gym_name`, `total_paid`(실제 결제금액), `start_date`, `end_date`, `special_terms` |
| `refund` | `total_days`, `used_days`, `used_amount`, `penalty`, `refund`, `per_day_loss`, `refs`(근거 id), `provisional` |
| `target`, `floor` | 목표 금액과 최저 수용선. 정하지 않으면 법정 환불액 |
| `stage` | 아래 단계 |
| `notified_on` | 해지 의사 도달일. 첫 통지 때 정해지고, 환불액이 이 날짜로 고정된다 |
| `deadline_on` | 답변 기한 |
| `attempts` | 통지와 재요청 횟수 |
| `last_reply`, `offered` | 마지막 답의 유형과 제시 금액 |
| `agreed_amount`, `deposit_due_on` | 합의 금액과 입금 기한 |
| `timeline` | `on`, `type`, `text` 기록 |

## 단계 (stage)

`ready → waiting ⇄ negotiating → agreed → closed`, 옆길로 `waiting → escalated → handed_off`.

| 단계 | 뜻 |
|---|---|
| `ready` | 계산이 끝났고 아직 알리지 않았다 |
| `waiting` | 알렸고 답을 기다린다 |
| `negotiating` | 답을 받았고 대응이 필요하다 |
| `escalated` | 내용증명을 보냈다 |
| `agreed` | 합의했고 입금을 기다린다 |
| `closed` | 입금을 확인했다 |
| `handed_off` | 1372 소비자상담센터에 접수했다 |

## 이벤트 (Event)

| `type` | 함께 보내는 것 | 결과 |
|---|---|---|
| `notice_sent` | `channel`: `sms` 또는 `call` | `waiting`. 첫 번째면 도달일을 정한다 |
| `reply_received` | `text`, 또는 버튼이면 `reply_type`과 `amount` | 유형에 따라 `negotiating`, `agreed`, `waiting` |
| `time_passed` | 없음 | 단계는 그대로. 다음 행동이 달라질 수 있다 |
| `agreement_recorded` | `amount` | `agreed` |
| `deposit_confirmed` | 없음 | `closed` |
| `escalation_sent` | 없음 | `escalated` |
| `handoff_done` | 없음 | `handed_off` |

`reply_type`: `accept`, `low_offer`, `refuse`, `list_price`, `visit`, `unknown`, 통화 결과용 `no_answer`, `callback`. `reply_type` 없이 `text`만 오면 LLM이 읽어 유형과 금액을 정한다.

## 행동 (Action)

서버가 "지금 할 일"로 돌려주는 값이다. `type`, `reason`, `warn`(제시액이 최저 수용선보다 적음).

`send_notice`, `wait`, `follow_up`, `counter`, `confirm_agreement`, `certified_mail`, `go_1372`, `remind_deposit`, `close`.

## API

| 경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/health` | | `ok`, `llm`(쓰는 구현 이름) |
| `GET /api/samples` | | 가상 계약서 목록: `id`, `label`, `contract` |
| `GET /api/rules` | | 근거 표: id별 `title`, `summary`, `url`, `verified` |
| `POST /api/cases` | `contract`, `today`, 선택 `target`·`floor` | `case`, `action`, `drafts` |
| `POST /api/cases/step` | `case`, `event`, `today` | `case`, `action`, `drafts` |

`drafts`는 양식 이름을 키로 하는 문안 묶음이다. 양식은 `data/templates/`에 있다.

| 행동 | 함께 오는 문안 |
|---|---|
| `send_notice` | `notice_sms`, `call_card`, `after_call_sms` |
| `follow_up` | `follow_up` |
| `counter` | `counter_refuse`, `counter_list_price`, `counter_visit`, `counter_low_offer`, `counter_unknown` 중 하나 |
| `confirm_agreement` | `accept_offer` |
| `wait`(단계가 `agreed`) | `confirm_agreement` |
| `remind_deposit` | `remind_deposit` |
| `certified_mail` | `certified_mail` |
| `go_1372` | `go_1372` |

## LLM 함수 (트랙 B)

`backend/app/agent.py`의 `llm` 객체가 아래 메서드를 가진다. 지금은 키워드로 판단하는 `FakeLLM`뿐이다.

| 메서드 | 입력 | 출력 |
|---|---|---|
| `read_reply(text)` | 업체 답장이나 통화 메모(500자까지) | `(reply_type, amount 또는 None)` |
| `polish(text, tone)` | 고정 양식 문안, 말투 | 다듬은 문안. `validate`를 통과하지 못하면 쓰지 않는다 |
| `extract_contract(...)` | 계약서 사진 | 아직 없다. 값, 확신도, 원문 위치를 돌려주도록 만든다 |

실제 구현이 실패하거나 호출 상한을 넘으면 `FakeLLM`과 고정 양식으로 계속 진행한다.

## 정책값 (`data/policy.json`)

법정 기한이 아니라 서비스가 정한 값이다. 화면에서 법정 기한처럼 보이지 않게 한다.

| 키 | 지금 값 | 뜻 |
|---|---|---|
| `penalty_percent` | 10 | 위약금 비율. 고시의 상한 |
| `wait_days` | 3 | 답을 기다리는 날 수 |
| `max_follow_ups` | 1 | 내용증명 전 재요청 횟수 |
| `deposit_days` | 3 | 합의 후 입금을 기다리는 날 수. 법정 환급 기한 확인 후 조정 |
