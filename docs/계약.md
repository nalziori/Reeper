# 계약

트랙 사이의 약속이다. 원본은 `backend/app/models.py`이고, 화면 쪽 사본은 `frontend/src/api.ts`다. 바꿀 때는 둘과 이 문서를 같이 고치고 세 명이 모두 본다.

## 원칙

- 서버는 사건을 저장하지 않는다. 화면이 사건을 보관하고, 요청에 실어 보내면 서버가 규칙을 적용해 돌려준다.
- 단계 전이와 금액은 서버 규칙이 정한다. LLM은 사건을 직접 바꾸지 않는다.
- 날짜(`today`)는 화면이 보낸다. 시연에서는 며칠을 건너뛴 날짜를 보낸다.

## 사건 (Case)

| 필드 | 뜻 |
|---|---|
| `contract` | `gym_name`, `total_paid`(실제 결제금액, 보증금 제외), `start_date`, `end_date`, `special_terms`, `unit`(`day`·`month`·`count`, 기본 `day`), `total_count`(월·회 단위 총수), `used_count`(회 단위 이용 횟수), `addon_value`(계약서에 적힌 부가상품 가액, 없으면 0), `security_deposit`(보증금) |
| `refund` | `total_days`·`used_days`(일이 아니면 개월 수·횟수), `used_days`, `used_amount`, `penalty`, `refund`, `per_day_loss`(하루 늦을 때 줄어드는 환불액), `addon`, `security_deposit`, `unit_label`(일·개월·회), `refs`(근거 id), `provisional` |
| `target`, `floor` | 목표 금액과 최저 수용선. 정하지 않으면 법정 환불액 |
| `stage` | 아래 단계 |
| `notified_on` | 해지 의사 도달일. 첫 통지 때 정해지고, 환불액이 이 날짜로 고정된다 |
| `deadline_on` | 답변 기한 |
| `attempts` | 통지와 재요청 횟수 |
| `last_reply`, `offered` | 마지막 답의 유형과 제시 금액 |
| `agreed_amount`, `deposit_due_on` | 합의 금액과 입금 기한 |
| `timeline` | `on`, `type`, `text` 기록 |
| `situation` | 사용자가 적은 상황 설명. 기본 빈 문자열, 1000자까지 |
| `strategy` | 상황 설명으로 세운 전략(아래 API 절). 없으면 `null` |

## 단계 (stage)

`ready → waiting ⇄ negotiating → agreed → closed`. 내용증명을 보낸 뒤에는 `escalated`에서 기다린다. 1372에 접수한 뒤에도 합의를 기록해 `handed_off → agreed → closed`로 진행할 수 있다.

| 단계 | 뜻 |
|---|---|
| `ready` | 계산이 끝났고 아직 알리지 않았다 |
| `waiting` | 알렸고 답을 기다린다 |
| `negotiating` | 답을 받았고 대응이 필요하다 |
| `escalated` | 내용증명을 보냈다 |
| `agreed` | 합의했고 입금을 기다린다 |
| `closed` | 입금을 확인했다 |
| `handed_off` | 1372 소비자상담센터에 접수했다 |

## 이벤트 (Event)

| `type` | 함께 보내는 것 | 결과 |
|---|---|---|
| `notice_sent` | `channel`: `sms` 또는 `call` | `waiting`. 첫 번째면 도달일을 정한다 |
| `call_attempted` | 없음 | 연결되지 않은 첫 통화를 기록한다. `ready`, 도달일, 환불액과 통지 횟수를 유지한다 |
| `reply_received` | `text`, 또는 버튼이면 `reply_type`과 `amount` | 유형에 따라 `negotiating`, `agreed`, `waiting`. 내용증명 발송 뒤 부재중·재연락 약속은 `escalated`로 돌아간다. 버튼으로 `accept`와 `amount`가 함께 오면 `low_offer`로 처리한다 |
| `counter_sent` | 없음 | 반박 발송과 새 답변 기한을 기록한다. `waiting`으로, 내용증명 발송 이력이 있으면 `escalated`로 돌아간다 |
| `time_passed` | 없음 | 오늘 기준 다음 행동과 문안을 갱신한다. 사건과 타임라인은 그대로 둔다 |
| `agreement_recorded` | `amount`. 금액을 보내면 0보다 커야 하고(0 이하는 409), 1372 접수 후에는 반드시 필요하다 | `negotiating` 또는 `handed_off`에서 `agreed` |
| `deposit_confirmed` | 없음 | `closed` |
| `escalation_sent` | 없음 | `escalated` |
| `handoff_done` | 없음 | `handed_off` |

`reply_type`: `accept`, `low_offer`, `refuse`, `list_price`, `visit`, `unknown`, 통화 결과용 `no_answer`, `callback`. `reply_type` 없이 `text`만 오면 LLM이 읽어 유형과 금액을 정한다.

## 행동 (Action)

서버가 "지금 할 일"로 돌려주는 값이다. `type`, `reason`, `warn`(제시액이 최저 수용선보다 적음).

`send_notice`, `wait`, `follow_up`, `counter`, `confirm_agreement`, `certified_mail`, `go_1372`, `remind_deposit`, `close`.

## API

| 경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/health` | | `ok`, `llm`(쓰는 구현 이름), `upload`(사진 읽기가 켜져 있는지), `calls_left`, `tokens_today` |
| `GET /api/samples` | | 가상 계약서 목록: `id`, `label`, `contract` |
| `GET /api/rules` | | 근거 표: id별 `title`, `summary`, `url`, `verified` |
| `POST /api/refund-preview` | `contract`, `today` | `Refund`. 규칙 계산만 수행하며 사건·문안·LLM 호출은 만들지 않음 |
| `POST /api/cases` | `contract`, `today`, 선택 `target`·`floor` | `case`, `action`, `drafts` |
| `POST /api/cases/strategy` | `case`, `situation`, `today` | `case`(`situation`과 `strategy`가 실린 사건), `llm_fallback` |
| `POST /api/cases/step` | `case`, `event`, `today` | `case`, `action`, `drafts`, `llm_fallback`, `analysis` |
| `POST /api/drafts/polish` | `case`, `kind`(양식 이름), `tone`(`polite`·`firm`) | `text`, `polished`. 사건은 돌려주지 않는다 |

| `POST /api/contracts/extract` | `image`(data URL) | `fields`(필드별 `Extracted`), `llm_fallback`. 사건을 만들지 않는다 |

요청 본문이 `MAX_BODY_BYTES`(기본 256KB)를 넘으면 413을 돌려준다. GET에는 적용하지 않는다. `POST /api/contracts/extract`만 사진 한도(`agent.MAX_IMAGE` + 4KB, 약 5.5MB)를 따로 쓴다.

`target`과 `floor`는 0원 이상의 정수다. 비우면 계산된 예상 환불액을 쓰며, `floor`는 `target`보다 높을 수 없다. 명시한 0원은 미입력과 구분한다. 업체 제시액(`offered`)도 0원을 그대로 기록한다. 다만 합의 금액(`agreement_recorded.amount`)은 0원보다 커야 한다(0 이하는 409).

`llm_fallback`이 참이면 실제 LLM이 실패했거나 일일 상한을 넘어 키워드 판단으로 대체한 것이다. 화면은 이를 알리고 버튼 입력을 권한다.

`analysis`는 붙여넣은 답장에서 LLM이 짚은 주장이다. 사용자에게만 보여 주는 값이고, 단계 전이·금액·`drafts`는 이 값을 보지 않는다. 버튼으로 고른 답, 가짜 LLM, 호출 실패, 짚은 것이 없는 경우에는 `null`이다.

| 필드 | 뜻 |
|---|---|
| `claims` | 답장 속 주장 목록. `quote`(답장 원문 그대로), `claim`(무슨 주장인지), `rule_id`(답에 쓸 근거 id, 없으면 `null`), `advice`(어떻게 답하면 되는지) |
| `note` | 지금 조심할 점 한두 문장. 없으면 빈 문자열 |

- `rule_id`가 `null`인 주장은 화면에 "확인 필요"로 보여 준다. 근거의 정식 명칭은 화면이 `GET /api/rules`에서 붙인다.
- 서버는 다음 항목을 버리고 보낸다: `quote`가 답장 원문에 없음, `advice`·`note`에 법령 이름·조문·고시·판례, 서버 계산값도 답장 속 금액도 아닌 금액, 사건에 없는 날짜, "무효·위법·불법·소송·고소".

`POST /api/cases/strategy`는 사용자의 상황 설명(1000자까지, 넘으면 422)으로 전략을 세워 사건에 싣는다. LLM 호출이 한 번 든다. 단계, 금액, 타임라인, `drafts`는 건드리지 않고 `strategy`를 보지도 않는다. 표시용이다. 사건을 연 뒤 언제든 부를 수 있고, 다시 부르면 전략을 새로 쓴다. 가짜 LLM, 호출 실패(`llm_fallback`이 참), 모든 항목이 버려진 경우에는 `strategy`가 `null`이다. 사건은 고정 양식과 버튼으로 끝까지 간다.

| `strategy` 필드 | 뜻 |
|---|---|
| `summary` | 이 건을 어떻게 풀지 두세 문장. 없으면 빈 문자열 |
| `grounds` | 쓸 근거 목록. `rule_id`(`data/rules.json`의 id), `why`(이 건에서 왜 쓰는지), `verified`(근거 표의 확인 여부, 서버가 붙인다) |
| `contract_points` | 특약 중 다툼이 될 조항. `quote`(특약 원문 그대로), `how_to_handle` |
| `objections` | 업체가 할 법한 반론. `objection`, `response` |
| `cautions` | 기대를 조정하는 안내. 예: 개인 사정만으로 위약금이 없어지지는 않는다. 업체 쪽 사유일 수 있으면 1372 상담을 권한다 |
| `questions` | 판단에 필요한데 자료에 없어 사용자에게 되물을 것 |

- 근거는 `rule_id`로만 가리킨다. 근거의 정식 명칭은 화면이 `GET /api/rules`에서 붙인다.
- 서버는 다음 항목을 버리고 보낸다: 근거 표에 없는 `rule_id`, 특약 원문에 없는 `quote`, 법령 이름·조문·고시·판례가 든 글, 서버 계산값도 상황 설명·특약 속 금액도 아닌 금액, 사건에 없는 날짜, "무효·위법·불법·소송·고소".
- 서버는 `situation`을 저장하거나 로그로 남기지 않는다.

`POST /api/drafts/polish`는 고정 양식 문안의 말투만 다듬는다(`agent.polished`). LLM 호출이 한 번 든다. 사건을 바꾸지 않는다. 가짜 LLM, 호출 실패, 숫자가 달라지거나 `validate`를 못 넘은 경우에는 원래 양식과 `polished: false`를 돌려준다. 없는 양식은 404, 통화 준비 카드(`call_card`)는 보내는 문장이 아니라 422, `tone`이 둘 중 하나가 아니면 422다. 화면은 자동 읽기를 쓸 수 없으면 말투 선택을 숨기고, 복사와 문자 앱 열기에는 고른 말투의 문안을 쓴다.


`POST /api/contracts/extract`는 계약서 사진에서 계약 값을 읽는다(`agent.extract_contract`). LLM 호출이 한 번 든다. 사진 읽기가 꺼져 있으면(`ALLOW_UPLOAD`가 `1`이 아니거나 가짜 LLM) 403, png·jpeg·webp data URL이 아니거나 너무 크면 422다. 호출이 실패하면 모든 값이 비고 `llm_fallback`이 참이다. 서버는 사진을 저장하거나 로그로 남기지 않는다. 화면은 `GET /api/health`의 `upload`가 참일 때만 사진 올리기를 보여 주고, 사진을 브라우저에서 줄여(긴 변 2000px 이하 JPEG) 보낸다. 읽은 값은 직접 입력 칸에 채우고 `check`가 참인 칸은 "확인 필요"로 표시한다. 읽는 값은 `gym_name`, `total_paid`, `start_date`, `end_date`, `special_terms`와, 계약서에 적혀 있을 때만 오는 `unit`(`day`·`month`·`count`), `total_count`, `addon_value`, `security_deposit`이다. 뒤의 네 값은 계약서에 없으면 `null`이고(`check`는 참) 화면은 기본값(일 단위, 0원)을 쓴다. `used_count`는 계약서에 없는 값이라 읽지 않는다. 사람이 확인한 값으로 `POST /api/refund-preview`와 `POST /api/cases`를 부른다.


`drafts`는 양식 이름을 키로 하는 문안 묶음이다. 양식은 `data/templates/`에 있다.

| 행동 | 함께 오는 문안 |
|---|---|
| `send_notice` | `notice_sms`, `call_card`, `after_call_sms` |
| `follow_up` | `follow_up` |
| `counter` | `counter_refuse`, `counter_list_price`, `counter_visit`, `counter_low_offer`, `counter_unknown`, `counter_penalty` 중 하나. `counter_penalty`는 유형이 `unknown`인데 답장이 위약금 비율을 주장했을 때 나온다(금액 없이 "위약금은 20%") |
| `confirm_agreement` | `accept_offer` |
| `wait`(단계가 `agreed`) | `confirm_agreement` |
| `remind_deposit` | `remind_deposit` |
| `certified_mail` | `certified_mail` |
| `go_1372` | `go_1372` |

## LLM 함수 (트랙 B)

`backend/app/agent.py`의 `llm` 객체가 아래 메서드를 가진다. `OPENAI_API_KEY`가 있으면 `OpenAILLM`, 없으면 키워드로 판단하는 `FakeLLM`이다.

| 메서드 | 입력 | 출력 |
|---|---|---|
| `read_reply(text)` | 업체 답장이나 통화 메모(500자까지) | `(reply_type, amount 또는 None)` |
| `polish(text, tone)` | 고정 양식 문안, 말투 | 다듬은 문안. `validate`를 통과하지 못하면 쓰지 않는다 |
| `extract_contract(image)` | 계약서 사진 | 필드(`FIELDS` 다섯, `MORE_FIELDS` 넷)마다 값, 확신도, 원문 위치 |

다른 트랙은 `llm`을 직접 부르지 않고 아래 모듈 함수를 부른다. 실제 구현이 실패하거나 호출 상한을 넘으면 이 함수들이 `FakeLLM`과 고정 양식으로 계속 진행한다.

| 함수 | 돌려주는 것 |
|---|---|
| `agent.read_reply(text)` | `(reply_type, amount, 대체했는지)`. `step`이 이미 쓴다 |
| `agent.analyze_reply(case, reply, action, today)` | `claims`, `note`, `fallback`을 담은 dict. `case`는 답장을 반영한 뒤의 사건이다. `step`이 이미 쓴다. 답장 한 건에 호출이 한 번 더 든다 |
| `agent.plan(case, situation, today)` | `summary`, `grounds`, `contract_points`, `objections`, `cautions`, `questions`, `fallback`을 담은 dict. `POST /api/cases/strategy`가 쓴다 |
| `agent.polished(kind, case, tone)` | `(문안, 다듬었는지)`. `tone`은 `polite` 또는 `firm`. 숫자가 하나라도 달라지거나 `validate`를 못 넘으면 원래 양식과 거짓. 없는 양식이면 `KeyError` |
| `agent.extract_contract(image)` | `(필드별 Extracted, 대체했는지)`. `image`는 `data:image/png·jpeg·webp;base64,...`, 약 4MB까지. 꺼져 있으면 `PermissionError`, 형식이 틀리면 `ValueError` |
| `agent.status()` | `llm`, `upload`(사진 읽기 켜짐), `calls_left`, `tokens_today`. `/api/health`가 싣는다 |

`Extracted`는 `value`, `confidence`(0~1, LLM이 스스로 매긴 참고값), `quote`(읽은 자리의 원문), `check`다. 못 읽은 값은 `value`가 `null`이다. 화면은 `check`가 참인 값을 사람에게 확인받고, 확인된 값으로 `POST /api/cases`를 부른다.

- 답장에 금액이 있으면 LLM이 수용이라고 읽어도 `low_offer`로 넘긴다. 받아들일지는 서버가 목표 금액·최저 수용선과 비교해 정한다.
- 환경변수: `OPENAI_API_KEY`, `OPENAI_MODEL`(기본 `gpt-6.1-terra`), `LLM_DAILY_LIMIT`(기본 300), `ALLOW_UPLOAD`(`1`이면 사진 읽기를 켠다. 기본은 꺼짐이다. 운영사무국이 합성 데이터라면 외부 AI에 보내도 된다고 답했으므로(2026-11-16) 합성(가상) 계약서만 올린다. 실제 계약서와 개인정보는 올리지 않는다).

## 정책값 (`data/policy.json`)

법정 기한이 아니라 서비스가 정한 값이다. 화면에서 법정 기한처럼 보이지 않게 한다.

| 키 | 지금 값 | 뜻 |
|---|---|---|
| `penalty_percent` | 10 | 위약금 비율. 고시의 상한 |
| `wait_days` | 3 | 답을 기다리는 날 수 |
| `max_follow_ups` | 1 | 내용증명 전 재요청 횟수 |
| `deposit_days` | 3 | 합의 후 입금을 기다리는 날 수. 법정 환급 기한 확인 후 조정 |
