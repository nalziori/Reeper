# 환불 규칙

계산 함수와 문안이 인용하는 법적 근거를 모아 둔다. **이 문서에 "확인됨"으로 적힌 내용만 코드와 문안에 쓴다.** 나머지는 원문을 직접 읽고 확인한 사람과 날짜를 적은 뒤 옮긴다.

이 문서는 일반적인 기준을 정리한 것이며 법률 자문이 아니다.

## 확인된 것

조사 과정에서 출처를 통해 확인한 내용이다. 코드에 넣기 전에 담당자가 원문을 한 번 더 읽는다.

| 내용 | 근거 | 상태 |
|---|---|---|
| 계속거래 소비자는 계약기간 중 언제든 해지할 수 있다 | 방문판매 등에 관한 법률 제31조 | 확인됨 (조사), 원문 재확인 필요 |
| 과다한 위약금 청구 금지, 차액 환급, 지연 시 배상 | 같은 법 제32조 | 확인됨 (조사), 원문 재확인 필요 |
| 헬스·피트니스업, 요가·필라테스업이 고시 적용 업종이다 | 계속거래 등의 해지·해제에 따른 위약금 및 대금의 환급에 관한 산정기준 (공정위 고시) 제3조제1항제3호 | 확인됨 (정본, 2026-11-18). 아래 확인 기록과 정본 원문 |
| 위약금은 총계약대금의 10%를 넘지 못한다 | 같은 고시, 공정위 의결서 인용 | 확인됨 (조사), 원문 재확인 필요 |
| 공제 기준 시점은 해지 의사표시가 사업자에게 도달한 시점이다 | 같은 고시 제5조 제1항 | 확인됨 (조사), 원문 재확인 필요 |
| 직접 이용하지 않았어도 기한이 도래해 이용할 수 있었으면 공급된 것으로 본다 | 같은 고시 제5조 제1항 | 확인됨 (조사), 원문 재확인 필요 |
| 소비자분쟁해결기준(체육시설업)은 개시 후 해지 시 이용일수 금액과 총 이용금액의 10%를 공제한다 | 소비자분쟁해결기준 | 확인됨 (조사), 원문 재확인 필요 |
| 소비자분쟁해결기준은 합의 권고 기준이고, 강행 근거는 방문판매법이다 | 보도·기고 | 확인됨 (2차 자료) |

## 확인이 필요한 것

아래는 아직 원문을 보지 못했다. 확인 전에는 계산과 문안에 쓰지 않는다.

| 항목 | 왜 필요한가 | 볼 곳 |
|---|---|---|
| 개시 전 해지 시 공제 금액 | 계산 함수의 분기 | 고시 별표 |
| 횟수제 PT의 단위대금 산정 방식 | 횟수제 계산 | 고시 별표 |
| 이용분을 일할로 계산하는 정확한 방식 | 기간제 계산의 기본식 | 고시 별표, 소비자분쟁해결기준 |
| 할인가·이벤트가로 결제한 경우의 기준 금액 | "정상가로 차감한다"는 업체 주장에 대한 대응 | 고시, 공정위 심결례 |
| 답변을 기다릴 기한과 환급 기한의 일수 | 기한 추적과 재요청 시점 | 방문판매법 제32조, 시행령 |
| 사은품·부대서비스(운동복, 락커 등) 공제 | 업체가 자주 공제하는 항목 | 고시 |
| 카드 수수료 공제 가능 여부 | 업체가 자주 주장하는 항목 | 공정위 약관 시정 사례 |

## 단정하면 안 되는 것

- **"정상가 차감은 무효"라고 단정하지 않는다.** 계약서에 단위요금이 명시되어 있거나 소비자의 서면 동의가 있으면 달리 볼 수 있다는 상담 사례가 있다. 문안은 "실제 결제금액 기준으로 계산해 달라"는 요청으로 쓰고, 다툼이 있으면 1372 상담으로 연결한다.
- **"한 번도 안 갔으면 대부분 돌려받는다"고 쓰지 않는다.** 개시일 이후 지난 날짜는 이용한 것으로 본다.
- **환불을 "받을 수 있다"고 확정하지 않는다.** "일반적인 기준에 따른 예상 금액"으로 표시한다.

## 계산식 (2026-11-15 팀 결정)

기간제 회원권 기준이다. 아래 다섯 가지는 규정이 있으면 규정대로, 없으면 조정 사례를 따른다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 1. 계산 단위 | 기간으로 정한 계약은 일 단위로 일할한다. 계약서에 월 단위로 적혀 있어도 개월이 아니라 날짜로 센다(2026-11-20 변경). 횟수로 정한 계약(PT·레슨)은 횟수로 센다. 적혀 있지 않으면 일 단위 | 고시 제2조제3호, 제5조제1항. 월 단위 일할은 아래 "월 단위 결정 변경"의 출처 |
| 2. 부가상품(사은품) | 계약서에 가액이 적혀 있을 때만 공제한다 | 고시 제5조제1항, 제6조제2항 |
| 3. 보증금 | 별도 약정이 없으면 전액 환급한다 | 고시 제5조제2항 |
| 4. 해지 의사 도달 당일 | 이용일에 넣는다. 개시일도 첫날부터 센다 | 규정 없음. [한국소비자원 조정 사례](https://www.kca.go.kr/odr/bj/br/osBjDecisionExamDetW.do?brdId=00000007&dataStts=Y&seq=1001711832)가 해지일을 이용일에 넣어 21일로 계산 |
| 5. 원 단위 끝전 | 이용분의 원 미만을 버린다. 최종 환불액은 따로 깎지 않는다 | 규정 없음. 같은 조정 사례가 이용금액 원 미만 절삭. 그 사례의 "환급액 1,000원 미만 버림"은 사용자 손해라 따르지 않는다 |

```
이용분 = 총계약대금 × (개시일부터 해지 의사 도달일까지의 일수, 양 끝 포함 ÷ 총 계약일수)   원 미만 버림
회 단위면 이용분 = 총계약대금 × (이용 횟수 ÷ 총 횟수)   원 미만 버림
위약금 = 총계약대금 × 10%
환불액 = 총계약대금 − 이용분 − 부가상품 가액(계약서에 있을 때) − 위약금 + 보증금   (0보다 작으면 0)
```

예시: 90일 60만 원 회원권을 개시 10일째에 해지하면 이용분 66,666원, 위약금 60,000원, 환불액 473,334원이다.

- 4·5번은 조정 사례 한 건(2013년, 소비자분쟁해결기준 2011년판 적용)에 기댄다. 이 사례는 `data/rules.json`에 없어서 문안에 근거로 쓰지 않는다(`AGENTS.md:8`). 통화 카드도 사례를 들지 않고, 날짜로 계산할 때는 도달 당일도 이용일에 넣는다는 계산 방식만 말한다(2026-11-20 C, `call_card.txt:16`). 당일 포함 여부는 고시 원문에 명시돼 있지 않아(아래 확인 기록) 팀이 정한 계산 방식이다. 앱은 첫 통지를 기록한 날을 도달일로 본다(`engine.py:74-75`). 실제로 업체에 닿은 날은 확인하지 않는다. 같은 방식의 최근 사례를 더 찾으면 이 표에 추가한다.
- 업체가 "해지일은 빼야 한다"고 하면 통화 준비 카드(`data/templates/call_card.txt`)의 대응 문장을 쓴다. 차이는 하루치 금액이다.
- 1~3번(단위, 부가상품, 보증금)은 아직 코드에 없다. 2단계에서 테스트를 먼저 쓰고 `rules.py`에 넣는다.

## 반론 유형과 대응 근거 (초안)

| 업체 답장 유형 | 대응 방향 | 인용할 근거 |
|---|---|---|
| 무응답 | 기한 경과 후 재요청, 이어서 내용증명 | 방문판매법 제31조, 제32조 |
| "환불 불가 상품이다" | 계속거래는 언제든 해지할 수 있음을 안내 | 방문판매법 제31조 |
| "정상가 기준으로 차감한다" | 실제 결제금액 기준 계산을 요청, 다툼 시 1372 연결 | 확인 필요 |
| "방문해야 처리된다" | 해지 의사는 이미 도달했음을 알리고 서면 처리를 요청 | 고시 제5조 제1항 |
| 법정액보다 적은 금액 제시 | 계산 내역을 제시하고 차액을 요청, 하한선(`floor`, 비워 두면 사건을 열 때의 예상 환불액) 미만이면 경고 | 고시 (10% 상한) |
| 법정액 이상 제시 또는 수용 | 합의 내용 확인 문안으로 넘어감 | 없음 |
| 표에 없는 주장 | 단정하지 않고 "확인 후 다시 연락드리겠다"로 답함 | 없음 |

- 답장 유형은 화면이 읽은 결과를 사용자가 확정한 뒤에 기록된다(#73, `/api/replies/read`). 자동 판단만으로 합의 같은 단계가 생기지 않는다.
- 반박을 되풀이하지 않는다(#75): 반박 문안을 `max_counters`(2, `data/policy.json`)번 보냈는데도 업체가 받아들이지 않으면 내용증명(`certified_mail`), 그 뒤에도 받아들이지 않으면 1372(`go_1372`)로 간다(`engine.next_action`). 이 횟수는 법에 정한 것이 아니라 앱이 정한 값이다. 하한선보다 적은 제시액이면 넘어가는 단계에서도 경고를 띄운다(`test_engine_paths.py::test_low_offer_after_max_counters_still_warns_and_good_offer_can_be_confirmed`). 내용증명 2항은 무응답과 거절 경로에 함께 쓰도록 "현재까지 환불을 받지 못하였습니다"로 바꿨다(#75).

## 팀 확인이 필요한 구현 (2026-11-15, C)

- **월 단위 결정 변경 (2026-11-20, C)**: 처음에는 해지 도달일이 속한 달(개시일 기준 한 달 단위)까지 이용한 것으로 셌다. 원문이나 조정 사례로 확인하지 않은 해석이었고, 개시 당일 해지에도 한 달치를 뺐다(예: 12개월 240,000원이면 20,000원). 확인한 자료의 헬스 회원권 사례에서는 이용분을 날짜로 일할했으므로 월 단위도 일 단위와 같은 식으로 바꿨다(`rules.py`). 같은 예의 이용분은 366일 중 1일, 655원이다.
  - 바꾸기 전 규칙으로 열고 아직 통지하지 않은 월 단위 사건은 기록을 그대로 둔 채, 화면이 새 예상 환불액을 보여 주고 희망 금액·하한선을 새 금액으로 맞출지 유지할지 고르게 한다(`OldMonthNotice.tsx`, `useCase.rebase`). 고르기 전에 보낸 첫 통지는 서버가 409로 거절한다(`engine.validate_transition`). 첫 통지 뒤의 사건은 금액이 이미 고정돼 그대로 둔다.
  - **일할 방식과 단가 기준은 출처가 다르다.** 이용분을 날짜로 일할한다는 방식은 아래에서 읽은 네 자료가 같다. 하루 단가를 무엇으로 정하는지는 다르다. 앱은 **실제 결제한 총액 ÷ 계약 일수**를 쓴다. 이 단가 기준의 출처는 특수거래과 답변과 소비자원 조정 사례다. 공정위 의결은 일할 방식은 뒷받침하지만 단가 기준은 다르다.

  - [공정위 약관심사과 답변(소비자24)](https://www.consumer.go.kr/user/bbs/consumer/380/940/bbsDataView/3141.do): 하루만 이용해도 한 달 이용으로 보는 조항은 약관법 위반 소지가 있다고 답했다. 체육시설업 표준약관(제10048호)은 이용일수와 일일 이용요금을 곱한 금액을 공제한다.
  - [공정위 특수거래과 답변(소비자24)](https://www.consumer.go.kr/user/bbs/consumer/380/940/bbsDataView/2902.do): 실제 납부한 금액을 기준으로 일할 계산이 원칙이라고 답했다. 앱의 단가 기준(실제 결제액 ÷ 계약 일수)은 이 답변을 따른다.
  - [한국소비자원 분쟁조정 사례(소비자24)](https://www.consumer.go.kr/user/ftc/consumer/trublmdatcase/116/selectTrublMdatCaseView.do?trublMdatCaseSn=12224): 헬스 이용분은 1,200,000원 × 118/365로 일할했고, PT는 30회 중 3회로 회차로 셌다. 일부는 요약 화면에서 읽었다.
  - [강원도 소비생활센터 상담 사례](https://consumer.gwd.go.kr/board_sample/33627)는 접속이 거부돼 이번에 읽지 못했다.

## 계산 범위와 근거 요약의 성격

- **이 계산은 소비자 사정으로 해지하는 경우만 다룬다.** 위약금 공제(고시 제4조제1항, 방문판매법 제32조)는 사업자 귀책 없는 해지가 전제다. 업체 잘못(시설 운영 중단, 약속한 강사·프로그램 불이행 등)으로 해지하면 `rules.py`의 10% 공제 금액을 쓰지 않는다. 근거 확인 화면이 해지 이유(내 사정·업체 잘못)를 묻는다(#142 뒤). 업체 잘못을 고르면 예상 환불액·협상 기준·업체에 보낼 문안을 보여 주지 않고 1372 상담을 안내하며 사건을 열지 않는다. 같은 화면에 비슷한 조정례가 어떻게 끝났는지 보여 준다(아래 "업체 잘못 유형별 조정례"). 대신 1372에 말할 사실(업체, 계약 기간, 결제 금액, 있었던 일)을 복사할 수 있는 글로 정리해 준다. 결제 금액은 사용자가 입력한 값이고, 앱이 계산한 환불액과 조문은 넣지 않으며, '있었던 일'은 사용자가 적은 그대로 들어간다(`FaultSummary.tsx`). '잘 모르겠어요' 선택지는 #142에서 뺐다. 금액과 흐름이 '내 사정'과 같았기 때문이다. 대신 업체 잘못 안내에 애매한 상황 예시를 두고, 애매하면 '내 사정'으로 금액을 먼저 보고 문자를 보내기 전에 1372에 물어보라고 안내한다(`Intake.tsx`). 엔진과 계산은 그대로다. G4·G5는 사업자 귀책 없는 해지를 위약금 공제의 전제로 두므로, 업체 잘못으로 해지하면 G4·G5를 위약금 공제 근거로 쓸 수 없다. 근거 표에는 업체 잘못 자체를 이유로 더할 배상의 근거도 없다(R32의 배상은 환급 지연에 관한 것이다). 그래서 업체 귀책을 반영한 별도 환불액은 산정하지 않는다. 화면은 해지 이유를 묻기 전에 개인 사정 기준 금액을 미리 계산하고(`api.preview`), 업체 잘못을 고르면 그 금액을 숨긴다. 폐업은 범위 밖이다(`docs/개발_계획.md`).
- **업종은 헬스·피트니스업과 요가·필라테스업만 다룬다.** 위약금 기준(총계약대금의 10%)이 확인된 업종이 이 둘이다. 근거 확인 화면이 업종을 묻고, 그 밖의 업종이면 계산 금액·문안 대신 1372 상담을 안내하며 사건을 열지 않는다(`Intake.tsx`).
- `rules.json` 요약은 원문을 줄인 문장이고, 끝에 붙은 "요청할 수 있다", "단정하지 않는다" 같은 말은 원문이 아니라 앱이 근거를 쓰는 방식에 대한 지침이다.
