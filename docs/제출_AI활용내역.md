② AI 활용 범위와 팀의 기여
코드·프롬프트·테스트·문서 초안, 평가 실행과 채점, 자료 조사는 대부분 AI(Claude Code)가 했다. 업체에 보내는 문안 양식도 AI가 초안을 쓰고 팀이 검토해 확정했다. 아래 네 가지는 팀이 직접 했다.
- 문제 정의: 처음 기획과 간이 설문(응답 17건)으로 "말을 꺼내기 어려워 환불을 미루는 청년"이라는 문제를 정했다. 배포 화면을 직접 써 보며 기다림 표시가 없는 문제와 첫 문자부터 법 조문을 드는 문제를 찾았다(B). AI는 통계·사례 조사를 맡았다.
- 서비스 설계: AI가 업체에 보낼 글까지 쓰게 한 실험(글 9건)을 보고 "계산은 코드, 읽기와 설명은 AI, 보내는 것은 사람"으로 정했다. 단계 전이와 사용자 확정(A), 에이전트와 출력 검사(B), 환불 계산식과 근거 표(C)는 각 트랙이 설계하고 AI가 구현했다.
- 핵심 의사결정: 사용할 모델, 배포의 하루 호출 상한 100회, 유료 실행 승인(B), 0원 합의 막기와 반박 2번(업체 사정 해지는 1번) 뒤 내용증명·1372 안내(A), 소비자분쟁해결기준을 근거 표에 넣지 않기(C), PR 병합 여부는 사람이 정했다.
- 결과 검증: 변경은 PR로 올려 다른 트랙 담당자가 검토했다(A→B→C→A). 근거 법령을 국가법령정보센터 원문으로 확인하고, 어려운 답장 100건(서비스 프롬프트를 보지 않은 AI가 초안)의 판정 기준을 정해 4건을 직접 확인했으며, 업체 사정 상황에서 위약금을 단정하는 조언을 잡는 채점을 만들었다(C). 역할 카드 답장 8건을 직접 쓰고 리뷰에서 평가셋에 없는 반례 문장 10개를 넣어 키워드 판단이 거절을 금액 제시로 읽는 위험한 오답 5건을 찾았다(A, #100). 평가 문장과 문서를 직접 읽고 누적 비용을 대시보드에서 확인했다(B).

④ 검증 및 한계 대응
- 확인 방법: 서버 테스트 365개(API 키 없이 가짜 LLM)와 브라우저 화면 흐름 점검 179항목을 통과했다. 실제 모델 평가는 실행 커밋, 호출 수, 한계를 같이 기록했다(누적 API 비용 2.35달러). 근거 표 법령과 화면에 보여 주는 사례 7건은 원문으로 확인했다.
- 결과: 어려운 답장 100건 유형 98/100(AI 없는 키워드 판단 42/100), 표기를 바꾼 답장 435건 435/435, 조언 10건 필수 근거 10~11/11·근거 표 밖 근거 0건. 계약서 이미지(깨끗한 내보내기 이미지)는 프롬프트를 고칠 때 본 12장 60/60, 처음 본 10장 50/50. 환불액은 가상 계약 27건과 실제 조정 사례 5건(4건 원 단위 일치, 1건 22원 차이)으로 대조했다.
- 설계로 막은 것: AI 출력에서 정해진 형식으로 적힌 금액을 서버 계산값과 대조하고, 근거 표에 없는 항목이나 글 속 법령 이름, 정해 둔 압박 표현이 있으면 코드가 버린다. AI가 읽은 답장은 사용자가 "맞아요"를 눌러야 기록된다. 근거를 못 찾은 주장에는 "확인 필요"를 붙이고 분석·조언은 "참고용"으로 표시한다. AI가 멈추거나 배포의 하루 상한(100회)을 넘으면 키워드 판단과 버튼으로 끝까지 진행된다.
- 주요 오류와 보완: 다른 사람이 쓴 답장 20건에서 미루는 답을 수용으로 읽은 위험한 오답 1건이 나왔다. 사용자 확정 단계가 막아 바로 합의되지 않는다. 이 자료에 맞춰 프롬프트를 고치지는 않았다. 정상가 주장과 함께 온 금액을 놓친 문제, 0원 제시를 버린 문제는 고쳤다. AI가 요약한 사례 2건은 원문과 대조해 틀린 판단을 고쳤다.
- 남은 한계: 조언의 틀린 해석이나 단정은 코드 검사로 못 잡는다(개시 전 해지 1건에서 위약금을 단정). 휴대폰으로 찍은 사진과 처음 보는 사용자의 사용성은 아직 재지 않았다. 업체 잘못인지는 판정하지 않고 조건부 금액과 1372 상담으로 안내한다. 어려운 답장 100건의 정답은 사람이 4건만 확인했다.
