# 부록: B 트랙의 AI 활용 내역 (파트 2)

> 초안 메모(제출 전에 지우기): 파트 1(`제출_B트랙.md`)의 6절을 풀어 쓴 부록이다. 「제품 안에서 쓰는 AI」(`gpt-6.1-terra`의 다섯 기능, 출력 검사, 평가 결과, 비용)는 파트 1의 1~5절과 7절, 소개서 부록의 「가. 제품 안에서 쓰는 AI」 절에 있어 여기서는 되풀이하지 않는다. 여기는 B 트랙이 **개발에서** AI를 어떻게 썼는지만 적는다. 2026-11-22 기준이고 건수는 `main` `f559ae7`에서 `git`과 `gh`로 셌다. 저장소로 확인되지 않는 내용(다른 AI 도구를 쓰지 않은 것, 사람이 읽은 범위)은 B 담당자가 2026-11-22에 직접 확인해 적었다.

## 3. 사람이 쥐고 있던 것

- **유료 호출 승인.** 실제 모델을 부르는 실행은 사람이 승인한 뒤에만 했다. 승인은 대화에서 실행 단위로 받았다. 한 번은 더 할 것이 있으면 다 하자는 말을 승인으로 보고 변형 435건을 돌렸다(약 0.25달러 추정).
- **키와 비밀 값.** API 키는 사람이 `backend/.env`(저장소 제외)와 배포 환경변수에 직접 넣었다. AI는 키 값을 출력하거나 입력하지 않았다. 심사용 잠금 주소의 값은 사람만 안다.
- **올릴지, 합칠지.** PR을 올릴지와 병합할지는 사람이 정했고 실행은 AI가 `git`과 `gh`로 했다. 사람이 시키지 않은 승인과 병합을 AI가 하려다 도구의 권한 검사에 막힌 적이 있다. 그 뒤로는 지시가 있을 때만 했다.
- **방향 결정.** 모델 선택, "업체에 보내는 글은 고정 양식", 배포 하루 상한, 기능 동결 뒤에 새로 나온 문제는 고치지 않고 한계로 적는다는 것.
- **팀과 주고받은 말.** 팀원에게 보내는 메시지는 AI가 초안을 쓰고 사람이 직접 전했다. PR 본문과 리뷰는 AI가 써서 B 계정으로 올렸고, 사람은 올라간 뒤에 읽었다.

## 4. AI를 쓰면서 지킨 것

- **금액은 AI가 만들지 않는다.** 문서와 문안의 금액은 `rules.py`의 계산 결과만 쓴다.
- **근거는 확인된 표 안에서만.** `data/rules.json`에 없는 법령이나 조문은 문안에 넣지 않는다(`AGENTS.md`).
- **제품 안 AI의 출력은 믿지 않고 검사한다.** 원문에 없는 인용, 서버 계산값이 아닌 금액, 법령 이름, 압박 표현이 있으면 그 항목을 버린다. 다시 시키지 않는다(파트 1의 3절).
- **테스트는 키 없이.** 서버 테스트는 가짜 LLM으로 통과해야 하고 `conftest.py`가 실행 환경의 키를 지운다.
- **평가 자료에 프롬프트를 맞추지 않는다.** 프롬프트를 고칠 때 본 자료의 점수는 "튜닝 후 점수"라고 적고(#41) 처음 보는 자료로 따로 쟀다. 어려운 답장 100건과 역할 카드 20건은 틀린 것을 보고도 프롬프트를 고치지 않았다.
- **숫자는 실행 기록과 함께.** 커밋, 호출 수, 토큰, 한계를 같이 적는다. 금액 추정에는 "추정"이라고 적는다. 누적 비용은 계산하지 않고 사람이 대시보드에서 읽은 값만 쓴다.
- **가상 데이터만 쓴다.** 계약서와 답장은 지어낸 것이다. 사진 읽기에는 합성 계약서만 넣었다(운영사무국 답, 2026-11-16). 실제 자료는 소비자24와 한국소비자원이 공개한 상담·조정 사례의 요약뿐이다(`eval/real_cases.md`, `eval/case_pool.jsonl`).
- **AI가 한 확인을 사람이 한 것처럼 적지 않는다.** 화면 확인은 "스크립트가 한 번 돌린 것"이라고 적는다.
- **담당 밖 파일을 바꾸면 PR 본문 맨 위에 이유를 적는다.**

## 5. AI와 일하며 생긴 문제와 대응

- 테스트가 깨진 커밋을 올린 적이 있다(#64). 테스트 결과를 `tail`로 자르고 `&&`로 이어서 실패를 보지 못했다. 다음 커밋으로 고쳤고, 그 뒤로는 결과를 그렇게 잇지 않는다.
- 워드 파일의 속성에 PC 사용자의 실명이 들어갔다(#82). 속성을 지우고 커밋을 바꿨다. 그 뒤로 문서 파일은 올리기 전에 속성을 확인한다.
- 팀원의 실명을 공개 저장소 문서에 올렸다(#129). 본인 의사에 따라 자리 표시로 바꾸고, 실명은 저장소 밖 파일에서 채우게 했다. 첫 커밋은 PR 화면에 남아 있다.
- 다른 트랙 담당자가 만들고 있던 것을 겹쳐 만들어 PR 두 개를 닫았다(#40, #46). 그 뒤로 화면과 경로에 걸친 일은 시작하기 전에 담당자에게 먼저 묻는다.
- AI가 틀리게 적은 것이 있었다. 사례 요지를 틀리게 적은 것 2건(요약 도구를 거친 것 하나, 조정 결정의 앞뒤만 읽은 것 하나. 둘 다 고침)과 리뷰에 "B 쪽 영향 없음"이라고 썼다가 바로잡은 것(#136)이다. 사례 풀의 조정 41건은 판단이 틀릴 수 있다고 한계에 적었다.
- 아무것도 잡지 못하는 테스트를 쓴 적이 있다(#175). 옛 조건을 끼웠을 때 실패하는지 확인해서 찾았고 고쳤다.
- AI가 스크립트로 한 확인을 "눌러 봤어요"라고 전해서, 다른 문서에 사람이 한 것으로 옮겨진 적이 있다(#123). 고쳐 달라고 했고 4절의 규칙을 두었다.

## 6. 쓰지 않은 것

- 업체에 보내는 글을 AI가 새로 쓰게 하지 않았다. 실험해 보고 그만뒀다. 제품에서 AI가 문안에 손대는 것은 말투 다듬기뿐이고, 검사에 걸리면 원래 양식을 그대로 쓴다.
- AI가 금액이나 사건 단계를 정하게 하지 않았다.
- AI가 전화하거나 문자를 대신 보내게 하지 않았다.
- AI에게 API 키나 잠금 값을 다루게 하지 않았다.
- 법률 특화 모델은 쓰지 않았다. 우리 키로 쓸 수 없었고 미국법 전용이었다.
